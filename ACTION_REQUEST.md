# Requested ecosystem action

This register turns the reform proposal into concrete public deliverables. It
does not assert that any organization accepted these requests.

| Owner | Requested deliverable | Required closure artifact | Related requirements |
|---|---|---|---|
| EMVCo | Publish a versioned browser/API/backend channel model and future closure-profile work item. | Public draft, issue identifier, or written position. | AR-01, AR-02, AR-04, AR-08 |
| Payment schemes / DS operators | Maintain synthetic account fixtures and a cross-requestor abnormal-network-traffic campaign profile. | Test-vector package and aggregate report format. | AR-04, AR-05, AR-08 |
| PCI SSC | Scope assessment guidance to the composed browser-to-authorization flow. | Assessment addendum or formal position. | AR-01 through AR-08 |
| 3DS Server providers / integrators | Implement bounded context, one-use transition controls, output allowlists, and trusted result retrieval. | Versioned conformance report. | AR-01, AR-03, AR-04, AR-07 |
| Gateways / Requestors | Enforce context consistency, reject equivalence, response filtering, and contextual authorization linkage. | Deployment attestation with test results. | AR-01, AR-03, AR-05, AR-07 |
| ACS operators / issuers | Test first-CReq, UI, OOB, timeout, and abandonment outputs against the stage profile. | Synthetic-fixture equivalence report. | AR-04, AR-05, AR-06, AR-08 |
| Acquirers / authorization systems | Verify authoritative authentication result and exact context before granting a related benefit. | Authorization-correlation test report. | AR-07 |

Status updates belong in [ACTION_REGISTER.csv](ACTION_REGISTER.csv). Each
update must include a date, source or contact channel, researcher-reported or
verified status, and a link or hash for any publishable closure artifact.
